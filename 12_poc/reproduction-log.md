## 要旨

1. 実施済み 23 TC を再実行し、TC 単位で**一致 16、不一致 7** だった（§3）[M]。
2. 不一致 7 件のうち 5 件（TC-010・013・016・027・028）は、**正式な結果を出したコードが残っていないため、正式な結果を再現できない**ものである。凍結タグ（F-4）がなく、12_poc/code が未コミットのまま、正式な実行の後に基盤と試験が直された。現行のコードで再実行すると、5 件ともレポートが「参考」とした新版の結果が再現した。残る 2 件（TC-017・TC-021）は、同じコードでの再実行で数値が一部違ったものである。
3. 正式な実行のうち、コードがバイト単位で同じ状態で再実行できたのは TC-002（v2）・TC-003（v1）・TC-009（v2）・TC-017（v1）の 4 TC だけである。参考の実行では TC-002 v3・TC-010 v3・TC-012 v2 がこれに当たる。このうち TC-002・TC-003・TC-009 は、判定と主要な指標が完全に一致した。
4. 生データの完全性はレポートどおりだった。50 件の SHA256SUMS（3,550 行）、集約ハッシュ `401e8671…e5df`、§3.2 表の SHA256SUMS のハッシュ 50 件、不一致 2 件（TC-010 の `eval.json`）、gzip の 66 件が、すべて一致した（§2）。評価器を生データから再実行した 8 件も、元の `eval.json` と指標が一致した。
5. レポートの誤記を 3 件見つけ、修正した（RL-E1〜E3）。修正した箇所には「再現時修正」と注記した。
6. README だけでは再現できない手順の欠落・環境依存を 13 件記録した（§4、RL-P1〜P13）。重いものは次の 3 件である。
   - 凍結時のコードを復元できない（RL-P1）。
   - 試験を並行に動かすと、負荷で結果が変わる TC がある（RL-P12）。
   - Windows の MAX_PATH を超えると TI 群の snapshot が起動できない（RL-P6）。

## 6. 本再現の限界と開示

- **独立性**: 再現者は実装者と別の AI エージェントだが、同じ機械・同じアカウントで実行した。人の立会人による再実行（POC-01 §2.6 の 4）の代わりにはならない [D]。
- **以前の再現の試み**: 同じ作業領域に、04:30Z〜05:16Z の別の再現の試み（同じ趣旨のもの）のログが残っていた。その試みの生データは、本再現が作業用の複写を作り直したときに削除された（一時領域の上書き。12_poc/data の元の生データには触れていない）。残ったログは `_repro/logs/prior-attempt-0430Z/` に写した。そのログでも、TC-013・016・018〜028（TC-022 は C-8）・TC-002 v2（中止）・TC-003（合格）・TC-012（合格）・TC-009（合格）・TC-010（不合格）は、本再現と同じ判定だった。本書の集計には使っていない。
- **ESPA 群の判定の再計算**: 評価器だけを動かす入口がないため、正式な生データからは再計算していない（RL-P7）。
- **TC-011・TC-004〜007**: 試験コードがなく、再現の対象外である。
