## 要旨（結論）

1. **系統 1 の 28 TC のうち、23 TC で凍結実行を行い、5 TC は未実施である** [M]。凍結コミットの版 0.1 の基準で凍結評価器が出した判定（正式な結果）の内訳は、**合格 12、不合格 5、判定保留 4、中止 2、未実施 5** である（§3）[M]。
   - 合格: TC-003・008・009・012・014・015・018・019・020・023・025・026 [M]
   - 不合格: TC-010・013・016・027・028 [M]
   - 判定保留: TC-001・017・021・024（閾値または p_max が TBD、または記録のみの TC）[M]
   - 中止: TC-002・022 [M]
   - 未実施: TC-004〜007・011 [M]
2. **これらの判定は、どれも合否判定と Gate 4 の証拠に使えない** [D]。凍結後の実行記録は 50 件ある [M]。50 件すべてで立会人がおらず（`witness=null`）、立会記録による凍結日時もない [M]。このため、作業ツリーの POC-01 版 0.4 §2.2.1 の W-1〜W-4 を 1 件も満たさず、全件が §2.5 の扱いになる [D]。凍結コミットの版 0.1 でも、合否記録への署名は立会人が行う（§2.1 の 5、§2.6）ので、上の判定は「実施チームの評価器の出力」にとどまる [D]。このうち 24 件は、旧版の結果を見た後に版を上げた実行でもある（W-5）[M]。
3. **不利な結果のうち、設計の主張に直接関わるものは 4 件ある**（§6）[D]。
   - (a) TC-010: PDP が遅いときに PEP が締切を守らず、write 以上を許可した（OpenFGA 構成で 12 件）[M]。
   - (b) TC-010: 誤応答を検知するまでの間に、誤った allow が出た（4 件）[M]。
   - (c) TC-002: わざと全域 permit にした誤りモデルの構成で、外部ゲストが付与されていない資源に allow を得た（OpenFGA 275 件、Cedar 90 件）[M]。
   - (d) TC-021: façade の関係書込 API が、他テナントの role を subject として受け付けた（1 件）[M]。
   - (a) は PoC の HTTP クライアントの欠陥だと実施者は記録している。この原因区分は作成者以外が確かめていない [D]。(c) は ADR-024 D24-08 の設計どおりの挙動で、ADR-024 §8 の再検討トリガーに当たる [D]。
4. **「合格」でも、仮説の一部は実証できていない** [D]。
   - TC-014: 鍵の誤撤去を検知できず、使用中の token 1,980 件のうち 1,566 件が拒否された [M]。
   - TC-008: OpenFGA の Check cache による stale を再現できなかった [M]。
   - TC-012: 正式な実行では、再提示攻撃が承認の束縛の検査まで届かなかった [M]。
   - 上の 3 件は、合否基準の指標に入っていないか、試験の設計上その検査に届かなかったものである [D]。
5. **事前登録からの逸脱は、計画書が起票した DEV-01〜DEV-12 とゲート統制の逸脱 GD-01 に加え、試験群が記録した 41 件と、本書が見つけた 7 件（DEV-13〜DEV-19 の候補）がある**（§5）[D]。基盤コードの変更は 22 件ある（§5.5）[M]。
   - 計画書の DEV-01〜DEV-12 と GD-01 は、作業ツリーの POC-01 版 0.4 §2.4.1・§2.5.1 による [D]。
   - 試験群の記録の内訳は、DEV-ESPA-01〜13、RK-DEV-01〜07、RK-EV-01〜03、RC-DEV-01〜10、本書が採番した TI-DEV-01〜08 である（§5）[D]。

6. **生データは 50 件とも、SHA256SUMS の照合で改変がないことを確かめた**（§4.3）[M]。例外は TC-010 の正式な実行 2 件の `eval.json` で、評価の再実行で上書きされたため記録上のハッシュと一致しない（DEV-12）[M]。
7. **系統 1 の値から 100 万人規模の性能・容量は言えない** [D]。TC-017 の最大の到着率は、1 cell 相当の平常負荷（ARC-13 §9.1 P1 の 7,742 Check/秒）に対して、OpenFGA 経路（56/秒）で約 0.7%、Cedar の in-process 経路（900/秒）で約 12% である[M][D]。tail latency は実測範囲の外へ外挿しない（ARC-13 §9.2）[D]。100 万人規模の数値は容量モデルと前提台帳による推定であり、実測ではない（§8）[D][A-001][A-045]。

## 8. 外挿の限界

1. **規模の差** [D]。
   - 系統 1 は、1 台のデスクトップ機（§2.1）で、全部品を単一プロセスずつ動かした構成である [M]。
   - TC-017 の到着率は、OpenFGA 経路で 19〜56/秒、Cedar の in-process 経路で 300〜900/秒、login で 30〜90/秒だった [M]。
   - 容量モデルの 1 cell 相当の平常負荷（P1）は 7,742 Check/秒、全体の基準は 42,009 Check/秒、利用者は 100 万人（A-001）である [D][^13][A-001][A-045]。
   - OpenFGA 経路の最大水準（56/秒）は P1 の約 0.7%、全体の基準の約 0.13% にあたる [D]。
   - データ量も、合成データの medium profile（unit 木の深さ 5、group の入れ子 3）で、P1 の 1.55 億 tuple より桁違いに小さい [M][D]。
2. **tail latency を外挿しない** [D]。ARC-13 §9.2 は、tail latency（p99・p99.9）を実測範囲の外へ外挿せず、cell 内のノード数も実測した最大数を超えて外挿しないと定めている [D][^13]。系統 1 の p99.9 は、1 ホスト・1 ノードの値であり、本番の cell の p99.9 の推定に使わない [D]。
3. **本書の値の位置づけ** [D]。100 万人規模の性能・容量について本書の値から言えるのは、次の 2 点だけである。
   - 測定系（開放ループ、全標本の保存、予定送信時刻からの計測、失敗の計数）が動いたこと（TC-017 のハーネスの妥当性）[M]
   - façade の追加遅延が、同じホストで p50 +1.8〜5.4 ms だったこと [M]
   - 100 万人規模の Check/秒、cell 数、KMS の署名枠などの数値は、容量モデル（ARC-13）と前提台帳（A-001・A-045 ほか）からの推定であり、実測ではない [D][A-001][A-045]。
4. **論理性質の外挿にも限界がある** [D]。
   - 生成型の試験（TC-002）で言えるのは、「C1 の構成と生成器の分布で、n=10,001 回で越境 0、残余率の 95% 上側限界が約 3×10⁻⁴」までである [D]。
   - 生成器の分布にない操作列（例: 本番の group の入れ子の深さ、実テナント数）は、この上限の範囲外である [D]。
   - C2（Cedar）は C-3 で中止したので、この上限は Cedar 構成には当てはまらない [D]。
5. **時間の分解能** [D]。ε（16.3 ms）と q を合わせた値より短い時間は比べられない（§2.3）。系統 1 の秒未満の反映時間を本番の SLO の判定に使わない [D]。
6. **製品・実装の代表性** [D]。
   - 系統 1 の AS は node-oidc-provider、PDP は OpenFGA v1.21.0 単体と Cedar wasm 4.13.0 である [M]。
   - TC-018〜020・022・023・028 は、試験群が作った参照実装を試験している（DEV-ESPA-08）[M]。
   - これらの結果は、採用する製品や本番の実装の適否を示さない [D]。
