## 基盤で見つけたが直していない事項（報告のみ）

| # | 事項 | 観測 | 直さなかった理由 |
|---|---|---|---|
| OB-TI-01 | 関係書込 API が `core/group#member` の循環と `max_depth`（CAM で 3）超過を拒否しない | TC-002 v1.0 の生成器が同一テナント内の group を循環して入れ子にすると、OpenFGA 構成は判定を続けたが、Cedar 構成はその tenant の判定が `deny_indeterminate`（`input graph has a cycle`）になり、正例の失敗率が C-3 の上限を超えた（C2 540/1550、C4 1086/2620）。fail-closed なので越境 allow は生じていない | 設計（authorization-model.md §3.6.3）は循環・深さの検査を基盤の階層サービスに置くが、PoC はそれを実装していない。façade に検査を入れると他の試験群（TC-021 の graph シナリオなど）の前提を変えるおそれがあるため、基盤は変えず、生成器側を CAM の制約に合わせた（TC-002 params v1.1、逸脱として記録） |
| OB-TI-02 | 外部ゲスト（資源側テナントの `external_member`）は G 段の規則 1（所属または外部付与）を満たすので、ドメインモデルが誤って全域 permit になると、付与されていない資源にも allow される | TC-002 の全域 permit 構成で X2（ゲストの付与外の資源）の allow が C3 275 件・C4 90 件、一覧項目 C3 480 件・C4 178 件。X1（文脈 tid・所属の不一致）は両構成とも 0 件 | 設計どおりの挙動（ADR-024 D24-08 は G 段で付与範囲を見ない）。ゲストの付与範囲の閉じ込めは R 段（ドメインモデル）に依存するという事実の記録 |
| OB-TI-03 | Cedar 構成の PDP façade プロセスが V8 の致命的エラー（`Fatal error ... unreachable code`、終了コード 2147483651）で落ちる | TC-002 v1.1（snapshot v3）で C2（Cedar・正しいモデル）・C4（Cedar・全域 permit）を各 2 回実行し、4 回とも途中（1,270〜12,510 件目の probe の後）で façade が落ちた。落ちる位置は毎回違う。落ちた実行の判定記録と tuple の op log を同じ版の adapter に単独で再生しても再現せず、Cedar adapter に 40 万回の check を流す単体負荷でもメモリ増加・異常終了はなかった。v1.0（group の循環が多数の判定を早期に評価不能にしていた）では C2・C4 とも最後まで動いた | 原因を特定できなかった（wasm 実行系の非決定的な異常の可能性があるが未確認）。基盤は変えていない。該当構成は「中止」として記録した |
